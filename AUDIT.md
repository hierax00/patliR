# patliR — pre-push methods & implementation audit

One row per computational/statistical function (pure I/O — `*_import`,
`*_export_smiles`, `prep_structure2d`, `patliR_load`, accessors — is left
out: nothing to audit, no formula or algorithmic choice involved). For each:
what it computes, the exact formula/algorithm, its theoretical grounding
with citation, whether patliR hand-rolls it or calls an existing
package/library function, and a one-line verdict on whether that choice is
the right one. Grounded against the source tree at commit `239bba4`
(2026-09-21) — every formula below was re-read from the actual `R/*.R`
source for this audit, not copied from `METHODS.md`.

Legend for **Implementation**: `hand-rolled` = plain R/base, no external
algorithm dependency; `pkg::fn()` = the actual call site delegates the
algorithm to that package.

## Chemical identity & physicochemistry

| Function | Computes | Formula / algorithm | Theory (citation) | Implementation | Optimal? |
|---|---|---|---|---|---|
| `prep_compounds()` | canonical structure ID | CDK canonicalisation, `Canonical`+`UseAromaticSymbols` flavour | — (data hygiene) | `rcdk::get.smiles()` | **Yes, with a known gap**: no InChIKey generator in `rcdk` on CRAN — documented in `DESIGN.md`, not silently assumed away. Correct call given the constraint; would improve with an `InChIKey` proxy package if one ever ships to CRAN. |
| `refdb_build()` (ChEMBL leg) | compound identity match | deterministic chain: CID→InChIKey→ChEMBL exact InChIKey→14-char skeleton→SMILES `flexmatch`→give up | — (identity, not similarity) | `httr2` direct REST calls | **Yes.** Fixed from a 100%-Tanimoto *similarity* search (wrong tool for an identity question) to a real identity chain — exactly right; each fallback step is strictly weaker and recorded in `match_type`, nothing hidden. |
| `compounds_classify()` | biosynthetic family | neural classifier (external) | Kim et al. 2021, *J. Nat. Prod.* 84:2795 (NPClassifier) | external web service | **Yes.** Training a classifier in-house would need thousands of labelled natural-product structures patliR has no reason to own; NPClassifier is the domain-appropriate published model (chosen over general ClassyFire for the plant-extract domain). |
| `compounds_similarity()` | pairwise structural similarity | Tanimoto = \|A∩B\|/\|A∪B\| on fingerprint bits | standard cheminformatics (Jaccard on bit vectors) | `rcdk::get.fingerprint()` + `fingerprint::fp.sim.matrix()` | **Yes.** Textbook operation; fingerprint generation is exactly the kind of "algorithm with real implementation detail" `DESIGN.md` reserves for a dependency, not layout. |
| `adme_local()` — 5 rules | drug-/lead-likeness | hard inequalities on MW/logP/HBD/HBA/TPSA/rot.bonds/AMR/atoms (see `METHODS.md` for exact thresholds) | Lipinski 2001, Veber 2002, Ghose 1999, Egan 2000, Oprea 2000 | hand-rolled (`with(out, ...)` boolean logic) over CDK descriptors | **Yes.** These are literally *defined* as fixed cutoffs in the source papers — no fitting possible, hand-rolling is strictly correct, a dependency would add nothing. |
| `adme_local()` — BOILED-Egg | GI absorption / BBB call | point-in-polygon test against two published ellipses | Daina & Zoete 2016, *ChemMedChem* 11:1117 | hand-rolled ray-casting (`.point_in_polygon()`) over digitized boundary CSVs | **Mostly yes, one known approximation**: uses CDK's ALogP as a WLogP proxy (no RDKit dependency) — correctly disclosed in the roxygen as "very likely right, not certified identical to SwissADME." Point-in-polygon itself needs no library. |
| `adme_local()` — `logs_esol` | aqueous solubility estimate | `0.16 − 0.63·logP − 0.0062·MW + 0.066·rotB − 0.74·aromProp` | Delaney 2004, *J. Chem. Inf. Comput. Sci.* 44:1000 (ESOL) | hand-rolled linear equation | **Yes** — it's a published closed-form regression equation, nothing to depend on. |
| `tox_local()` | PAINS/Brenk structural alerts | SMARTS substructure matching, 480+105 patterns | Baell & Holloway 2010; Brenk et al. 2008 | `rcdk::matches()` | **Yes.** SMARTS matching is a real algorithm (subgraph isomorphism) — correctly delegated to CDK rather than hand-rolled; bundled pattern lists cross-validated against RDKit's own compiled catalogs before shipping (documented provenance, not transcribed from memory). |
| `tox_safetyome()` | systemic safety-liability flag | table lookup against a curated 500-gene panel | Liu et al. 2026, *Toxicological Sciences* 209(3) | `clusterProfiler::bitr()` (ID mapping only) + local CSV lookup | **Yes.** No algorithm to speak of beyond ID mapping, which already reuses the same mapper `network_enrich()` uses — no duplicated ID-mapping logic across the package. |

## Targets & disease

| Function | Computes | Formula / algorithm | Theory (citation) | Implementation | Optimal? |
|---|---|---|---|---|---|
| `targets_disease_filter()` / `targets_disease_profile()` | target↔disease association | Open Targets' own aggregated 0–1 score across evidence types | Open Targets Platform (aggregation methodology is theirs, not re-derived here) | `httr2` GraphQL calls, hand-rolled query strings | **Yes.** Re-deriving an evidence-aggregation score from genetics/literature/clinical/etc. in-house would duplicate a maintained, versioned platform for no benefit; querying it live (cached) is the right call. ## Network core

| Function | Computes | Formula / algorithm | Theory (citation) | Implementation | Optimal? |
|---|---|---|---|---|---|
| `network_build()` | bipartite compound-target graph | dedup (max-weight per pair) + bipartite assertion | — (construction) | `igraph::graph_from_data_frame()` | **Yes.** Trivial construction, no reason for anything heavier. |
| `network_centrality()` | degree / betweenness / hub score | raw `igraph`, then bipartite normalisation `deg/\|opp.mode\|`, `betw/B_max` (closed-form piecewise, `.network_bipartite_bmax()`) | Freeman 1978; **Borgatti & Everett 1997**, *Social Networks* 19:243 | `igraph::degree/betweenness/eigen_centrality()` (raw) + hand-rolled `B_max` formula | **Yes.** `igraph` has no built-in two-mode normalisation — hand-rolling the closed-form `B_max` (not an approximation) is the correct call, and it replaced a genuinely broken prior approach (`hits_scores()$hub`'s RNG-seeded degenerate eigenspace) with the deterministic Perron eigenvector. |
| `network_hub_penalty()` | promiscuity-adjusted target score | `N·p·log(1/p)` | none claimed (TF-IDF-like, explicitly flagged non-monotone in `ROADMAP.md`) | hand-rolled two-line formula | **Partially — flagged, not fixed.** The formula itself needs no library, but its own docs admit the name "penalty" oversells a non-monotone weight. Correctly self-critical rather than presented as settled. |
| `network_proximity()` | disease-module distance | closest distance `d(S,T)`, degree-matched permutation null, `z = (d_obs−mean)/sd` | **Guney et al. 2016**, *Nat Commun* 7:10331 (Eq. 2); Menche 2015 | `igraph::distances()` (BFS) + hand-rolled resampling | **Yes.** BFS shortest-path is `igraph`'s job; the degree-matched null (the actual statistical contribution) is correctly hand-rolled since no package implements this exact bipartite-graph-aware resampling. |
| `network_synergy()` | topological separation `s_AB`, Cheng P1–P6 | `⟨d_AB⟩ − (⟨d_AA⟩+⟨d_BB⟩)/2`; truth table on `(separated, proximal_a, proximal_b)` | **Menche et al. 2015**; **Cheng, Kovács & Barabási 2019**, *Nat Commun* 10:1197 | `igraph::distances()` (once per condition, submatrix-reused across every pair) + hand-rolled Menche arithmetic | **Yes.** Verified against 300 random graphs to `1e-12` against a reference `separation.py`-style computation — not just "looks right," actually checked. Singleton convention (`⟨d_AA⟩=0`, not Menche's `NaN`) is disclosed as patliR's own choice with its direction of bias stated, not silently substituted. |
| `network_module_robustness()` — clustering | community detection | Leiden maximising Newman `Q` (default); Barber's `Q_B` (bipartite mode); HDBSCAN (contrast) | **Traag, Waltman & van Eck 2019**, *Sci Rep* 9:5233; **Barber 2007**, *Phys Rev E* 76:066102; Beckett 2016 | `igraph::cluster_leiden()`; `bipartite::computeModules()` | **Yes.** This is precisely `DESIGN.md`'s own stated line: Barber's `Q_B` maximisation is NP-hard with a decade of literature behind it, not something to hand-roll — `bipartite` is a justified `Suggests`, guarded, namespace-only. HDBSCAN kept explicitly as a *contrast*, not silently presented as equally appropriate (`ont` warns it degenerates to single-linkage on this integer metric). |
| `network_module_robustness()` — R-index | percolation robustness | mean largest-component fraction over targeted/random removal | **Schneider et al. 2011**, *PNAS* 108:3838; Albert/Jeong/Barabási 2000 | hand-rolled removal loop | **Yes.** A removal simulation is exactly geometry/procedure, not a packaged algorithm — correctly hand-rolled, no dependency would help. |
| `network_motifs()` | 3-node feed-forward triples | table join over 2-step paths, closing-edge check | Milo et al. 2002 (motif *shapes* only — no null model run, disclosed) | hand-rolled `merge()` | **Yes**, and honestly scoped: the roxygen is explicit that this is enumeration, not statistically-enriched motif detection — doesn't borrow Milo et al.'s statistical claim without doing the statistics. |
| `network_bowtie()` | bow-tie decomposition | strongly-connected-component analysis on STRING's directed "actions" channel | Broder et al. 2000, *Comput. Netw.* 33:309 | `igraph::components(mode="strong")` + hand-rolled raw-file STRING parsing | **Yes.** SCC-finding is `igraph`'s job; STRING's directed channel is fetched as a raw flat file rather than via `STRINGdb$new()` specifically because no `STRINGdb` method exposes it — a deliberate, documented choice to avoid downloading the entire undirected interactome just for an alias table. |
| `network_kegg_topology()` *(new)* | directed pathway topology | KGML `<relation>` parsing, entry→gene resolution, cartesian expansion over multi-gene entries | KEGG's own curated pathway topology (no statistical claim made) | `KEGGREST::keggGet()`/`keggConv()` (fetch/ID-map) + hand-rolled `xml2` parsing | **Yes.** `KEGGgraph`/Rgraphviz were deliberately not used for parsing a handful of XML tags (`<entry>`, `<relation>`, `<subtype>`) — that's squarely "reimplement layout" territory per `DESIGN.md`, not an algorithm worth a heavy dependency; bulk `keggConv()` (one call per species) instead of per-gene calls is the right efficiency choice, verified live. |
| `network_enrich()` | pathway/GO over-representation | hypergeometric (Fisher) test vs. a background | Boyle et al. 2004 (background-specification framing); Yu et al. 2012 (`clusterProfiler`) | `clusterProfiler::enrichGO/enrichKEGG()`, `ReactomePA::enrichPathway()` | **Yes.** ORA is a mature, correctly-implemented statistical test in Bioconductor's reference tool for this — reimplementing it would be pure risk for zero benefit. The actual patliR contribution is correctly scoped to what's missing upstream: `universe = "project"` fixes a real background-specification bias (Timmons, Szkop & Gallagher 2015) the library itself does not correct for you. |
| `network_degeneracy()` — direct mode | pairwise functional convergence | GO semantic similarity, best-match average (BMA); annotation-count-matched permutation null | Wang et al. 2007, *Bioinformatics* 23:1274; Schlicker et al. 2006 (BMA); Edelman & Gally 2001 (degeneracy concept) | `GOSemSim::termSim()` (pairwise term similarity matrix) + **hand-rolled** BMA combiner reproducing `GOSemSim::combineScores()` exactly | **Yes, and notably verified, not assumed**: the hand-rolled BMA was checked against real `GOSemSim::clusterSim()` output on thousands of synthetic cases with zero mismatches before being trusted — the hand-roll exists only because the *naive* per-permutation `clusterSim()` call would cost ~60h; the fast version is mathematically identical, not an approximation. |
| `bias_audit()` | outlier flag | `mad_score = (degree−median)/MAD` | **Leys et al. 2013** (median/MAD over mean/SD for skewed data) | `stats::mad()` | **Yes.** One-line application of a well-established robust-statistics formula; no library needed beyond base R's own `mad()`. |

## Ranking, reporting, disease network

| Function | Computes | Formula / algorithm | Theory (citation) | Implementation | Optimal? |
|---|---|---|---|---|---|
| `rank_candidates()` | combined ranking | Robust Rank Aggregation — order-statistic (beta-distribution) correction over per-criterion ranks | **Kolde, Laur, Adler & Vilo 2012**, *Bioinformatics* 28(4):573-580 (verified DOI live) | `RobustRankAggreg::aggregateRanks()` | **Yes.** This is exactly `DESIGN.md`'s "depend for algorithms" case, applied consistently: the closed-form null-model correction is non-trivial statistics with a canonical reference implementation by the method's own author — hand-rolling it would risk a subtly wrong p-value with no upside. `full = TRUE` was confirmed correct against the installed package's actual behaviour, not assumed from the paper alone. |
| `rank_candidates()` — Pareto front | non-dominated sorting | pairwise dominance check, `O(n²)` per tier | classic multi-objective optimisation (no single canonical citation attached — described only as "NSGA-II-style" informally) | hand-rolled | **Yes at this scale.** A real NSGA-II implementation solves a harder problem (evolutionary search) patliR does not need — this is a one-off sort over an already-fixed candidate list (tens to hundreds of rows), where `O(n²)` per tier is negligible; a dependency would be over-engineering. |
| `report_generate()` | HTML report | string templating | — (presentation) | hand-rolled (base R `paste0`/`sprintf`), deliberately not `rmarkdown` | **Yes, and re-confirmed during development**: `rmarkdown`/`pandoc` would need `pandoc` on every end-user's machine, which is not a safe assumption to make (a plain R install does not bundle it) — exactly the failure mode a package function must not depend on. A handful of HTML tables needs no dependency at all. |
| `plot_disease_network()` *(new)* | compound-target-disease network | force-directed layout + convex hull per disease | — (visualisation) | `igraph::layout_with_fr()` + `grDevices::chull()` | **Yes.** Reuses the exact hull pattern `plot_chemical_space()` already established and verified, rather than inventing a second convex-hull implementation — one algorithm, two call sites, consistent with `DESIGN.md`'s "reimplement layout" principle (`chull()` is base R, no dependency either way). |
| `plot_chemical_space()` | 2D/3D projection | PCA (`prcomp`, scaled) or UMAP | classical PCA; McInnes et al. 2018 (UMAP) | `stats::prcomp()` (base R) / `umap::umap()` (optional) | **Yes.** PCA needs no dependency at all (base R has always shipped it); UMAP is correctly gated as an optional `Suggests` since it's a genuinely different, heavier algorithm some users will not need. |
| `plot_admet_radar()` | 6-axis bioavailability radar | hand-rolled polar coordinates (`x=r·sinθ`, `y=r·cosθ`) | Daina et al. 2017, *Sci Rep* 7:42717 ("pink zone" boundaries) | hand-rolled `ggplot2` geometry | **Yes.** Polar-axis placement is layout, not algorithm — squarely the "reimplement it" half of `DESIGN.md`'s rule; the *boundaries* drawn (the actual scientific content) come from the cited paper, not invented. |
| `plot_upset()` / `plot_adme_upset()` | set-intersection combinatorics | exact-intersection counting | — (combinatorics, no statistics) | hand-rolled bar+dot matrix | **Yes.** `DESIGN.md` explicitly records that `UpSetR`/`ComplexUpset` were deliberately not taken as dependencies for exactly this reason — the geometry is simple enough to own. |
| `plot_target_chord()` | target-target adjacency arcs | hand-rolled quadratic Bézier, arc height scaled to node span | Krzywinski et al. 2009 (arc-diagram idiom, not a specific formula) | hand-rolled `geom_path()` Bézier, not `geom_curve()` | **Yes**, and deliberately so: a constant `geom_curve()` curvature would make a short-hop arc invisible next to a long one on a 1-D node line (unlike `plot_network_degeneracy()`'s 2-D force layout, where a constant curvature is fine) — the hand-roll exists because the built-in geom's implicit behaviour is wrong for this specific layout, not out of dependency-avoidance alone. |

## Net read

Every genuinely non-trivial **algorithm** (Barber's `Q_B`, RRA's order-statistic
correction, KGML parsing, SMARTS matching, ORA's hypergeometric test, GO
semantic similarity, UMAP) is delegated to a maintained package, each with
an explicit citation and — where it mattered — live verification rather
than an assumption from documentation. Every genuinely **layout/geometry**
piece (polar axes, convex hulls, Bézier arcs, UpSet bars, HTML tables) is
hand-rolled in base R/`ggplot2`, matching `DESIGN.md`'s own stated rule
consistently across all ~35 functions audited here, not just the ones the
rule was originally written about. The only two open, self-disclosed
limitations are `network_hub_penalty()`'s non-monotone formula (flagged in
`ROADMAP.md`, not silently shipped as settled) and BOILED-Egg's ALogP-for-
WLogP proxy (disclosed in the roxygen, not claimed identical to SwissADME).
Nothing found in this pass needed a library swapped for hand-rolled code or
vice versa.
